Before you ask.

Answers to common questions about bytecode comparisons on BOT Chain.

Why don't my bytecodes match exactly? ▼
Solidity appends compiler metadata (such as solc version and IPFS compilation details) to the end of your contract. Furthermore, immutable variables set in the constructor are inlined directly into runtime bytecode. Twin Check strips the CBOR metadata tail and isolates immutable offsets so you can see whether the actual executable code is identical.
What's PUSH0 and why does Twin Check warn about it? ▼
PUSH0 is an EVM instruction introduced in Shanghai (Solidity 0.8.20+). Chains that run the Paris EVM specification do not support PUSH0, which will cause transactions to revert with an invalid opcode error. Twin Check scans for 0x5f and advises compiling with evmVersion: "paris" if detected.
Do you need my source code? ▼
No! Twin Check operates purely on runtime bytecode fetched directly from the RPC nodes of Bohr Testnet and BOT Chain Mainnet. You never need to upload or expose proprietary source code.
Is recording on-chain required? ▼
No. You can run unlimited free bytecode and view comparisons in your browser without connecting a wallet or spending gas. Recording is an optional step if you want a permanent on-chain badge proof on BOT Chain.
Can anyone record a report for my contract? ▼
Anyone can run and record a report, but Twin Check automatically checks the contract's owner() method on-chain. If the recorder address matches the contract owner, the badge permanently displays a distinct "Checked by owner ✓" badge.
